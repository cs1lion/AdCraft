# 实机演示端到端测试方案

> 建立：2026-09-28
> 目标：**项目启动实机演示**——前后端真实启动、真实访问，完成
> 「创意输入 → 文本 → 音频 → 视频 → 优化流程 → 剪辑 → 成片」全链路。
> 关联：`last-hundred-meters-plan.md`（本方案是它的执行前置）、`docs/agents/engineering-standards.md`
> 素材：`demo-materials/`（见该目录 README）

---

## 0. 验收哲学（先说清楚不测什么）

| 不作为通过标准 | 作为通过标准 |
|---|---|
| 成片画质精美 | 链路每一环都真的产生了产物并落盘 |
| 模型生成质量高 | **UI 元素存在、可见、可点** |
| 提示词写得漂亮 | **操作有正确响应与状态反馈** |
| 无任何已知缺陷 | **约束正确**：非法输入被拦住，错误信息可行动 |
| — | 降级路径可查询、不静默 |

**一句话**：我们验收的是**产品的骨架和交互的诚实度**，不是模型的艺术水平。
一个按钮点了没反应、一个错误被吞掉、一个加载转三天——这些是不过的；
成片是 480p 糊了点，那是可以过的。

## 1. 测试分级

| 级别 | 名称 | 时长 | 频率 | 阻断演示 |
|---|---|---|---|---|
| **L0** | 冒烟 | ~5 min | 每次改动 | 是 |
| **L1** | 主链路 | ~60–90 min | 每次演示前 | 是 |
| **L2** | 可交互性 | 随 L1 | 每次演示前 | 是 |

| **L4** | 负例与约束 | ~30 min | 每周 | 否（但要记录） |
| **L5** | 留痕归档 | 随 L1 | 每次演示 | 是 |

## 2. L0 冒烟（5 分钟，先证明"能起来"）

| ID | 动作 | 通过判据 | 失败怎么办 |
|---|---|---|---|
| L0-1 | 启动后端 | 端口监听 + `GET /api/v1/health` 200 | 先修环境，别谈功能 |
| L0-2 | 启动前端 | dev server 监听 + 首页 200 + 无白屏 | 看 console 首屏错误 |
| L0-3 | 前端代理连通 | 前端发起一个 `/api/v1/health` 返回 200 | 代理配置问题 |
| L0-4 | 打开画布页 | 项目列表渲染出至少 1 项或明确的空态 | 看路由与 API |
| L0-5 | console 扫描 | 无未捕获异常、无红色 error 级报错 | 记录但不阻断（登记缺陷） |

> **纪律**：L0 不过就不要开始 L1。演示当天 L0 不过 = 演示取消，
> 不要把环境问题带进后面的用例里污染结论。

## 3. L1 主链路（S0 → S12）

> 每一步都记录：**前置状态 / 用户操作 / 期望 UI 反馈 / 落盘产物**。
> 任一步"卡住"超过阈值即记缺陷，不允许"跳过继续"。

### S0 建项目

| 项 | 内容 |
|---|---|
| 前置 | 停在项目列表页 |
| 操作 | 点击「新建项目」→ 填写名称 → 确认 |
| 期望反馈 | 跳转到画布；项目出现在列表；URL 带 workflow id |
| 产物 | `/projects` 出现新条目 |
| 失败信号 | 按钮无响应 / 表单不校验空名 / 跳转 404 |

### S1 创意输入（自然语言起点）

| 项 | 内容 |
|---|---|
| 前置 | 空画布 |
| 操作 | 在引导对话里输入一句创意（用 `demo-materials/scripts/` 里的 brief） |
| 期望反馈 | 输入框回显；发送后出现「思考中/生成中」状态；流式或最终返回一段文本 |
| 产物 | 一条 chat 消息落库 |
| 失败信号 | 无 loading 态 / 报错但界面不红 / 文本为空却不提示 |

**负例 N1.1**：发送空内容 → 必须被拦住（按钮禁用或明确报错），不能发出空请求。
**负例 N1.2**：发送后立刻刷新 → 会话不丢失（或明确提示未保存）。

### S2 剧本生成

| 项 | 内容 |
|---|---|
| 前置 | S1 完成 |
| 操作 | 触发「生成剧本」/ 走 front desk 进入 script 节点 |
| 期望反馈 | 出现生成中状态；完成后剧本正文可见、可编辑 |
| 产物 | script 节点 + 资产 |
| 失败信号 | 长时间无状态反馈 / 剧本为空但显示成功 / 无法编辑 |

**关键**：这里同时验 `script` 节点与 `role_registry`（script_writer）。台词是否好不在验收范围，
但**"台词能被改"必须在**（后面故事改写要用）。

### S3 角色与场景

| 项 | 内容 |
|---|---|
| 操作 | 生成角色 / 场景，或从资产库挑（`demo-materials/images/`） |
| 期望反馈 | 缩略图可见；角色卡可打开；一致性相关字段可查 |
| 产物 | character / scene 资产 + 库条目 |

**负例 N3.1**：未绑定 `character_asset_id` 的角色 → 一致性闸门应给出 warning 且可一键修复
（这是 Dramagic 式闸门，验它是否真的在 UI 上出现）。

### S4 分镜

| 项 | 内容 |
|---|---|
| 操作 | 生成 storyboard |
| 期望反馈 | 分镜列表出现，镜头卡含景别/运镜/时长；可跳转 |
| 产物 | storyboard 节点 + shots |

**负例 N4.1**：scene-3d 存在镜头时间空隙时，`check_storyboard_span` 的 finding
应当**在 UI 上可见**（当前后端算了但不返回——这是已知缺陷，演示前需确认是否已修）。

### S5 视频生成

| 项 | 内容 |
|---|---|
| 前置 | 分镜就绪 |
| 操作 | 对某镜头点「生成」 |
| 期望反馈 | 明确的进行中状态；可取消或至少可离开页面后回来看到状态 |
| 产物 | video 资产落盘，可在播放器里播 |
| 失败信号 | 转圈无超时 / 失败无原因 / 刷新后状态丢失且无处可查 |

> **这是演示最容易翻车的一步**：真实模型调用慢、可能失败、要花钱。
> 演示前必须先跑一次"热身"确认额度与连通，且**准备好失败话术**。

### S6 配音 / BGM

| 项 | 内容 |
|---|---|
| 操作 | voice-cast 生成台词语音；加 BGM |
| 期望反馈 | 音频可试听；时长显示真实测得值 |
| 产物 | speech_audio + bgm 资产 |

**负例 N6.1**：单句重合成入口 —— 后端 `/scene-3d/voice-cast-resynth-line` 已有，
但前端零引用。演示前确认是否有入口；无则记为"已知缺失"，**不要临场硬凑**。

### S7 时间线剪辑

| 项 | 内容 |
|---|---|
| 操作 | 打开全局时间线；拖动/裁剪 clip；加转场 |
| 期望反馈 | 轨道渲染；播放头可拖；改动后有保存反馈 |
| 产物 | timeline 版本 +1 |

**负例 N7.1**：重叠 clip → 应有合法提示而非静默接受或崩溃。

### S8 成片渲染

| 项 | 内容 |
|---|---|
| 操作 | 点「渲染成片」 |
| 期望反馈 | 进度可见或至少状态可查；结束给成片预览 |
| 产物 | final mp4 落盘，**必须有音轨** |

> 🔴 **演示前必查项**：当前 `test_resolved_bgm_renders_real_audio_into_final_video`
> 是失败的（G7 从未真正执行）。**成片没声音就是当场演示事故**。
> 这条必须在演示前跑通并留证。

### S9 成片预览与二次修改

| 项 | 内容 |
|---|---|
| 操作 | 播放成片；尝试替换某段 |
| 期望反馈 | 可播；替换有确认与撤销 |

## 4. L2 可交互性（每步都做，不单列时间）

逐页过一遍，规则很简单：

| 检查项 | 判据 |
|---|---|
| 可见性 | 按钮/输入框真实可见，不是 `display:none` 的摆设 |
| 可点性 | 点了必须有反应：状态变化、弹层、或明确禁用态 |
| 禁用语义 | 禁用按钮要**说得出为什么**（tooltip 或文案），不能只是灰着 |
| 表单校验 | 空值/超长/非法格式被拦住，且提示具体 |
| 长任务 | 进行中状态可见；离开页面再回来状态还在 |
| 加载/空/错误三态 | 每个数据区域都要有这三种状态，不能只有成功态 |

**重点排查对象**（来自实测复核）：
- 3D 工作台「撤销修改」是整体回退，不是撤销栈 → 演示时要说清是"回到上次保存"
- 导演指令栏闸门失败曾被显示成灰色 note 而非红色错误 → 已列为必修
- 3D 草稿刷新即丢 → 演示中刷新前务必先保存

## 5. L3 状态反馈专项

| 场景 | 期望 |
|---|---|
| 额度不足 / 429 | 明确告知 + 给出可行动建议（充值/降级/换模型） |
| provider 不可用 | 显示是哪个 provider、为什么、怎么办（**Blender 不可用目前前端零提示，必修**） |
| 长任务超时 | 超时要有明确失败态，不是无限转圈 |
| 部分成功 | 成功的部分要展示，失败的部分单独列出 |
| 静默降级 | 任何降级都必须有可查询的状态标记（工程标准 §4） |

## 6. L4 负例与约束（每周 / 演示前一晚）

| ID | 负例 | 期望 |
|---|---|---|
| N1.1 | 空创意发送 | 被拦 |
| N1.2 | 超长文本（>10k） | 被拦或截断并告知 |
| N2.1 | 剧本生成中途取消 | 状态收敛，不留幽灵 running |
| N3.1 | 角色未绑资产 | 一致性 warning 可行动 |
| N4.1 | 分镜有空隙 | finding 可见 |
| N5.1 | 视频生成失败 | 有原因、可重试 |
| N6.1 | 无音频资产时渲染 | 明确失败或明确降级并告知 |
| N7.1 | clip 重叠 | 合法提示 |
| N8.1 | 未解析库素材时直出 | **当前会静默剥掉 clip** → 必须改为可见提示（最后一米重点） |
| N9.1 | 断网/后端挂掉 | Health 状态可见，功能按钮合理禁用 |

## 7. L5 留痕规范

每次演示/验收必须留下：

```
demo-materials/runs/<时间戳>/
├── summary.md          # 结论：通过/失败/已知缺失，附统计
├── report.json         # 机器可读：用例 ID × 状态 × 耗时
├── console.log         # 浏览器 console 导出
├── backend.log         # 后端日志
├── screenshots/        # 每步关键界面
└── outputs/            # 真实产物：音频/视频/成片
```

**纪律**：`SKIP` 必须写原因；"没测"不能记成"通过"；
一个已知缺陷要在 summary 里显式列出，不靠记忆。

## 8. 测试实施流程

### 8.1 一次完整演示的推进节奏

| 阶段 | 时长 | 动作 |
|---|---|---|
| 准备 | 30 min | 启环境 → L0 冒烟 → 跑热身生成任务确认额度 → 清理旧项目 |
| 主链路 | 60–90 min | 按 S0→S8 顺序推进，每步记录 |
| 收尾 | 20 min | 导出产物、整理截图、写 summary |

### 8.2 Agent 与人的分工

| 环节 | 谁做 | 说明 |
|---|---|---|
| 启动环境、L0 | Agent | 可脚本化、可复核 |
| 素材准备、路径校验 | Agent | 见 `demo-materials/` |
| 后端链路调用、产物核对 | Agent | 用 pytest + curl 组合 |
| UI 逐屏走查 | Agent（浏览器）+ 人复核 | Agent 出证据，人判断"对不对" |
| 模型生成质量判断 | **人** | 机器判不了"好不好看" |
| 成片观感验收 | **人** | 同上 |
| 缺陷定级与是否阻断演示 | **人** | |

### 8.3 缺陷分级

| 级别 | 定义 | 演示处理 |
|---|---|---|
| **S1 阻断** | 主链路某步走不通 | 必须当天修 |
| **S2 可见** | 界面元素缺失/错误状态显示错 | 当天修（属于"UI/UX 正常存在"） |
| **S3 体验** | 能用但别扭（无 undo、刷新丢失） | 记入 backlog，演示时口头说明 |
| **S4 已知缺失** | 后端有、前端无入口 | 记入可达性清单，演示时不提 |

### 8.4 回归门槛

演示前必须满足：

- `npm run check:endpoint-reachability` 通过（死端点数不增）
- 后端 replica+scene3d 全绿（含 G7 音频用例）
- L0 + L1 全通
- 已知 S1/S2 缺陷为 0

## 9. 演示话术预案（诚实版）

如果演示中某个环节失败，**不要说"正常应该可以"**。用这套说法：

- 额度类：「模型额度这次用完了，这是设计内的失败路径——你看它明确告诉了我们原因。」
- 已知缺失类：「这条链路后端已经做完了，前端入口还没接，这是我们今天要收敛的清单第一条。」
- 质量问题：「这版的目标是打通链路不是画质，画质是下一步的事。」

**诚实的失败演示 > 掩盖的完美演示**。而且上面每一条都在强化"我们知道自己的问题在哪"。

## 10. 素材使用说明

见 `demo-materials/README.md`。要点：

- **参考视频**：`videos/replica-reference/` —— 拉片复刻输入，含真实剪辑结构的开源短片
- **文案脚本**：`scripts/` —— 创意输入 brief、故事改写前后对照
- **图片**：`images/` —— product / character / scene 三类，固定 seed 可复现
- **音频**：`audio/` —— 配音与 BGM 参考

所有素材来源、许可、体积记录在 `SOURCES.md`，禁止混入无许可来源。

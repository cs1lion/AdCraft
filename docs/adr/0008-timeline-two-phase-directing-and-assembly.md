# ADR 0008: Timeline 的双相角色 — 生成前指导与生成后组装

## Status

Accepted（2026-09-26）。作为 [ADR 0007](./0007-timeline-driven-production.md) 的扩展：0007 建立了时间线作为编排层，本 ADR 回答由此引出的架构问题——**时间线应该只做最终拼接剪辑，还是也应该做生成前指导？对齐信息如何传给视频模型？**

## Context

ADR 0007 落地后，时间线目前只承担**生成后组装**：节点各自生成素材 → auto-clip 落到轨道 → editing 节点 ffmpeg 拼接混音。这留下一个结构性缺口：每个 video 节点生成时**看不见**时间线——它不知道自己是第几个镜头、时间窗是 3.0–5.0s、对白在第几秒开始。后果正是用户观察到的："5 秒的镜头各自好看，接起来对不上"。

与此同时，本次会话已逐个建好了生成前指导所需的全部零件：语音时间线（measured TTS 时长）、SceneScript 唇形关键帧、3D 预演轨迹、2.5D 深度重投影环绕、场景操作批次、白模模式。缺的是**把这些零件按时间窗切片并送进视频模型的那根管线**。

约束：视频模型（Seedance/Agnes/Hailuo）不接受"时间线"这种参数——它们接受的是**参考视频、参考图序列、参考音频、以及 depth/normal/flow 控制信号**。任何"把时间线传给模型"的设计都必须先经过一次**渲染化的翻译**。

## Decisions

### 1. 时间线是**一条时间线的两个相位**，不是两套系统

```
                ┌────────────────────────────────────────────┐
                │  Timeline（timelines / tracks / clips 三张表）│
                └────────────────────────────────────────────┘
                     ▲                              ▲
         Phase 1 导演态（生成前）          Phase 2 剪辑态（生成后）
                     │                              │
         clip = 镜头意图：时间窗 + 语音切片    clip = 媒体：生成好的素材
               + 预演切片 + 生成参数            + 裁剪/转场/混音参数
                     │                              │
              video 节点消费切片生成          editing 节点 ffmpeg 组装
                     │                              │
                     每次生成完成，clip 就地刷新（既有 upsert 语义保留用户排列）
```

- **同一个 clip 对象**贯穿两个相位：生成前它是"意图"（时间窗 + 该窗的语音/预演切片引用 + 生成参数），生成后它是"媒体"（指向生成产物的 asset 指针 + 裁剪/转场/音量）。既有的 `upsert_auto_clip_for_node`（rerun 就地刷新、保留用户排列）正是两个相位之间的转换点。
- **不做两套时间线**：生成前指导层若独立建表，立刻产生"导演表和剪辑表哪份为准"的问题。一张表、一个 clip、两个字段面相（`intent` 元数据 + `media` 指针）是唯一自洽的模型。

### 2. 对齐信息传给视频模型的方式：**渲染化的参考切片，而非时间线参数**

核心原则：**模型永远收不到时间线，收到的是"排练片"**。时间线是导演的谱；模型看到的是按谱排练出来的画面与声音。按控制力排序的三条通道，全部已在 codebase 中存在：

| # | 通道 | 传送内容 | 现有实现 | 降级 |
|---|---|---|---|---|
| 1 | **运动参考视频** | 该镜头时间窗的 3D 预演/2.5D 环绕切片（相机轨迹、人物 blocking、口型全部烘进像素） | `seedance_adapter` Agnes `videos[]` + `<Video N>` 占位；Seedance reference video | 5 关键帧图（ADR 0005 §4a） |
| 2 | **音频参考** | 该时间窗的语音切片 | `audio_inputs`（Agnes `<Audio N>`）/ `generate_audio`（Seedance） | 无音频参考，口型按预演参考 |
| 3 | **控制信号** | depth/normal/flow 通道或 2.5D 深度图 | `control_signals` schema + `previs_control_level` 指纹 | 按 provider 能力省略并标记 |

**时间对齐靠构造保证，不靠模型理解**：每个镜头按自己的精确时长独立生成，最后拼接——全局时序从不依赖模型"听懂"时间线。这就是 ADR 0007 §1"大问题拆成小问题"的完整含义：时间线负责把 30 秒拆成 6 个 5 秒，模型每次只需要面对 5 秒 + 它的切片。

### 3. 切片是标准的交付降级点

时间窗切片（`app/services/timeline_media_slice.py`）在参考投递前执行：视频参考按窗 frame-accurate 重编码（`-c copy` 会按关键帧切割、漂移一个 GOP），音频参考同窗裁剪。任何 operational 失败（源缺失、窗口越源、ffmpeg 失败）→ `sliced=False` + warnings，调用方**降级为投递整个资产并知晓对齐变弱**（工程标准 §4，不静默）。

### 4. 两相的 UI 是同一面板的两个模式

GlobalTimelinePanel 增加"导演态/剪辑态"切换（复用既有轨道 UI）：导演态下 clip 显示其镜头参数与绑定参考；剪辑态下显示媒体与裁剪参数。默认剪辑态（既有行为不变），导演态由 scene-3d/voice-cast 节点存在时自动提示。

## 与 ADR 0007 的关系

本 ADR 不改写 0007 的任何决策：时间线仍是编排层不是执行层；仍是节点生成、时间线编排、editing 渲染。本 ADR 补充的是 0007 §2.4"video 节点执行时，根据 timeline_metadata 的时间段，从 scene-3d 预演中提取对应时间段的参考帧"的**机制**——即上文第 2、3 条。

## Withdrawn candidates（如实记录）

- **把时间线/起止时间作为参数传给视频模型。** 视频模型不接受结构化时间参数；强行编码进 prompt 等于把不可执行的自然语言塞进生成器，控制力为零。
- **只做生成后组装（维持现状）。** 放弃生成前指导 = 放弃本会话建起的唇形/预演/语音时间线在生成侧的价值，镜头之间继续"各自好看、接起来对不上"。
- **只做生成前指导、不要剪辑态。** text-to-video 的漂移决定了再精确的指导也需要确定性组装；ffmpeg 组装廉价且可复现。
- **为导演态新建独立数据表。** 立刻产生双源一致性问题；clip 两相一面是唯一自洽模型。

- [x] 参考通道结构：`AgentCanvasSeedanceInputCompiler` 已按 image/video/audio inputs 分流；previs/voice-cast → video 的 binding 投递已存在

- [x] **P1 后端接线**（2026-09-26）：`app/services/timeline_window_slicer.py`——video 节点执行时经 `_default_timeline_window_resolver` 读取自身 timeline clip 时间窗，对绑定的 video/audio 参考切片后把 provider 输入改写为切片 data URL；报告随执行上下文 `timeline_slicing_report` 发布（可查询）。降级链完整：无时间窗/源不可解析/切片失败 → 保留整资产 + warning，resolver 故障不阻塞生成。8 项测试锁定（含 executor 接线）
- [x] **P2 导演态镜头意图摘要**（2026-09-26）：检查器在导演态为 video/voice clip 显示只读意图徽章（时间窗 + 说话人 + 生成侧契约说明：video → 该窗预演/语音参考切片驱动生成；voice → 该窗台词音频驱动 3D 唇形）。有意设计为**只读摘要而非第二套输入**——窗口与说话人的编辑复用下方既有字段，避免同值双源
